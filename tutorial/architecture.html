1. Oversampled FPS (Farthest Point Sampling) ¶

Purpose. Pick a large set of candidate centers that uniformly covers the event. PoLAr‑MAE intentionally oversamples (more seeds than the final number of patches) so that C‑NMS can later thin them out while keeping coverage.

Where implemented.

  • Function sample_farthest_points() — polarmae/layers/grouping.py:94-180. Wraps PyTorch3D's CUDA implementation (_C.sample_farthest_points, line 178).
  • Called from PointcloudGrouping.forward() — polarmae/layers/grouping.py:345-350: 
    possible_centers, idx = sample_farthest_points(
    points[..., :3].float(),
    K=self.num_groups,
    lengths=lengths,
    random_start_point=True,
)  # (B, G, 3)

Tensor shapes.

TensorShapeMeaning
Input points[..., :3](B, N, 3)XYZ of all event points
Input lengths(B,)Number of valid points per event
Output possible_centers(B, G, 3)FPS‑selected seed centers (G = num_init_groups)
Output idx(B, G)Indices into the original cloud

Algorithm. Iterative greedy: at every step the next sample is the point with the largest distance to the already‑sampled set. random_start_point=True randomizes the first sample, so seed sets vary between training iterations.

Default (ViT‑S/5). num_init_groups = 256 seeds — see _5voxel_tokenizer() in polarmae/layers/tokenizer.py:155-174. The "oversampling" is relative to the eventual number of retained patches (≤ context_length = 512 after C‑NMS).

2. C‑NMS (Centroid Non‑Maximum Suppression) ¶

Purpose. Greedy de‑duplication of FPS seeds. Patches whose ball neighbourhoods would overlap too much get suppressed; the retained centers approximate a voxelization of the pointcloud without aliasing.

Where implemented.

  • Python wrapper cnms() — extensions/cnms/cnms/__init__.py:11-75. Returns the suppressed centroid list, valid lengths, and a permutation index.
  • CUDA / CPU kernels for the greedy reduction — extensions/cnms/csrc/ (greedy_reduction_cuda.cu, greedy_reduction_cpu.cpp). Selects, in descending‑overlap‑count order, the seeds to keep and marks the rest retain=False.
  • Driven from PointcloudGrouping.forward() — polarmae/layers/grouping.py:357-374: 
    group_centers, lengths1, grouping_idx = cnms(
    possible_centers,
    overlap_factor=self.overlap_factor,   # 0.72 by default
    radius=self.group_radius,
    K=self.num_groups,
    lengths=possible_lengths,
)
group_centers = group_centers[:, :self.context_length]
lengths1      = lengths1.clamp_max(self.context_length)

Mechanism.

  1. Run a self‑ball‑query on the FPS seeds with query radius 2·radius·overlap_factor (line 48 of __init__.py).
  2. For each seed, count how many other seeds fall inside its overlap radius (overlap_counts, line 60).
  3. Sort seeds by overlap count (descending), then greedily keep a seed only if none of its already‑kept neighbours overlap it. This is the _ext.greedy_reduction kernel (line 66).
  4. Reorder so retained centers come first; truncate to context_length.

Tensor shapes.

TensorShape
Input centroids(B, G, 3)
Input lengths(B,)
Output centroids (reordered)(B, G, 3)
Output lengths (retained per event)(B,)

Default (ViT‑S/5). overlap_factor=0.72, radius = 5/(768·√3/2), context_length=512 — set in _5voxel_tokenizer().

3. Ball Query + Masking ¶

Purpose. Two distinct operations combined visually in the diagram:

  1. Ball Query (+ per‑patch reduction): build each patch by gathering points around its center, then trim to a fixed point count K.
  2. MAE masking: randomly mark a fraction of the resulting tokens as "masked" and hide them from the encoder.

3a. Ball query (patch construction) ¶

Where implemented. Inside PointcloudGrouping.forward(), polarmae/layers/grouping.py:398-424 (PyTorch3D's ball_query) followed by an energy‑topk or FPS reduction.

_, idx, _ = ball_query(
    group_centers[:, :, :3].float(),
    points[:, :, :3].float(),
    K=self.group_upscale_points,   # 256 = K_big
    radius=self.group_radius,
    lengths1=lengths1, lengths2=lengths,

# Per-patch reduction: K_big -> K

elif self.reduction_method == 'fps':

Reduction helpers select_topk_by_energy (lines 182‑233) and select_topk_by_fps (lines 235‑265) live in the same file. The PoLAr‑MAE config uses reduction_method='fps'.

Finally, patch coordinates are centered (subtract group center, line 474) and rescaled by group_radius (line 476‑479), matching PointNeXT.

4. mini‑PointNet (Patch Embedding) ¶

Purpose. Turn each patch (a set of K points) into a single token embedding of dimension D = embed_dim. This is the "Patch Embedding" arrow into the encoder in the diagram.

Where implemented. Class MaskedMiniPointNet (with equivariant=False) — polarmae/layers/pointnet.py:9-74. Instantiated inside the tokenizer at polarmae/layers/tokenizer.py:53:

self.embedding = MaskedMiniPointNet(num_channels, token_dim)

Internal layout (matches the right‑hand "mini‑PointNet" panel of the diagram):

# pointnet.py:17-22 — first MLP (the "MLP" before "max")
self.first_conv = nn.Sequential(
    nn.Conv1d(channels, 128, 1, bias=False),       # 4 -> 128
    MaskedBatchNorm1d(128),
    nn.ReLU(inplace=True),
    nn.Conv1d(128, 256, 1),                        # 128 -> 256
)
# pointnet.py:24-29 — second MLP (the "MLP" after "cat")
self.second_conv = nn.Sequential(
    nn.Conv1d(512, 512, 1, bias=False),            # 512 -> 512
    MaskedBatchNorm1d(512),
    nn.ReLU(inplace=True),
    nn.Conv1d(512, feature_dim, 1),                # 512 -> D (=384 for ViT-S)
)

The forward pass (lines 35‑74) does:

  1. Reshape (B, T, K, C) → (B·T, K, C) if the input is per‑patch (line 39‑43).
  2. First MLP (per‑point, with masked BN): (B·T, C, K) → (B·T, 256, K) (lines 47‑51).
  3. Max pool ("max"): (B·T, 256, K) → (B·T, 256, 1) (line 57).
  4. Concat ("cat") of global + local: (B·T, 512, K) (lines 59‑61).
  5. Second MLP: (B·T, 512, K) → (B·T, D, K) (lines 63‑67).
  6. Final max over points: (B·T, D), then reshape back to (B, T, D) (lines 70‑73).

Padding handling. MaskedBatchNorm1d (polarmae/layers/masking.py:205-297) computes statistics only over valid points using point_mask. Patch padding is also zeroed out before the tokenizer (polarmae/layers/grouping.py:482).

Default channels (ViT‑S/5). num_channels=4 (xyz + energy), token_dim = embed_dim = 384.

5. Equivariant mini‑PointNet ¶

Purpose. An order‑aware variant of mini‑PointNet used only on masked patches for the per‑point energy task. Adding a positional encoding over the point index breaks the permutation invariance of the standard PointNet so the decoder can attribute predicted energies back to specific points within the patch.

Where implemented. Same class MaskedMiniPointNet instantiated with equivariant=True — polarmae/layers/pointnet.py:9-74 — plus the PointOrderEncoder module — polarmae/layers/pointnet.py:96-110 — built on a sinusoidal TimeEmbedding (lines 77‑94). The instance is created in the pretraining task: polarmae/models/ssl/polarmae.py:75-79:

self.equivariant_patch_encoder = MaskedMiniPointNet(
    channels=3,
    feature_dim=self.embed_dim,
    equivariant=True,
)

Internal layout (matches the right‑hand "Equivariant mini‑PointNet" panel):

  • Two parallel MLPs on the right diagram are the same first_conv applied to the points and the order‑embedding produced by the PointOrderEncoder(256).
  • The two are summed (pointnet.py:54): 
    if self.equivariant:
    feature = feature + self.position_encoder(points).transpose(2, 1)
  • The remainder (max → cat → MLP → max) is identical to mini‑PointNet.

PointOrderEncoder takes the sequence [0, 1, …, K-1] (line 107), runs it through a sinusoidal embedding of dimension 256, then a linear layer (lines 99-103). Note this indexes per‑patch positions, not 3D coordinates — hence the "(0, 1, …, 31)" label in the diagram.

Tensor shapes.

TensorShapeMeaning
Input masked_groups[..., :3](M, K, 3)XYZ of points in masked patches (M = total masked tokens in batch)
Input masked_point_mask(M, 1, K)Valid point mask
Output(M, D)Patch embedding, D=384

6. Encoder (Transformer Encoder) ¶

Purpose. Standard ViT‑style self‑attention over the visible tokens only. The encoder learns rich contextual representations of the un‑masked patches.

Where implemented.

  • Wrapper: TransformerEncoder — polarmae/layers/encoder.py:14-139. Bundles the tokenizer, learned positional encoder, masking module, and the Transformer.
  • Transformer body: Transformer class — polarmae/layers/transformer.py:30-146; constructed via make_transformer(arch_name='vit_small') → vit_small() at transformer.py:187-197.
  • Per‑block layer (norm → multi‑head attn → norm → MLP): Block in polarmae/layers/block.py; attention in polarmae/layers/attention.py.
  • Positional encoder: LearnedPositionalEncoder — polarmae/layers/pos_embed.py:35-69. A 3‑D MLP (Linear(3,128) → GELU → Linear(128, 384)).

Tensor shapes (forward).

TensorShapeMeaning

7. Decoder (Transformer Decoder) ¶

Purpose. Inflate the encoder outputs (which carry information only at visible positions) plus learned mask_token embeddings into a sequence of features covering all token positions. The result is then fed to the two reconstruction heads.

Where implemented. Class TransformerDecoder — polarmae/layers/decoder.py:10-41. It is just a thin wrapper around the same Transformer as the encoder, but with fewer layers and post‑norm.

Wiring (polarmae/models/ssl/polarmae.py:93-101):

# Encode visible tokens
encoder_output = self.encoder.transformer(
    out['x'], out['pos_embed'], unmasked
).last_hidden_state                                   # (B, T, D)

# Replace masked positions with a learned mask token
corrupted_embeddings = (
    encoder_output * unmasked.unsqueeze(-1)
    + self.mask_token * masked.unsqueeze(-1)
)                                                     # (B, T, D)

# Decode over all positions
decoder_output = self.decoder.transformer(
    corrupted_embeddings, out['pos_embed'], out['emb_mask']
).last_hidden_state                                   # (B, T, D)
masked_output  = decoder_output[masked]                # (M, D)

Tensor shapes. Input and output are (B, T, D). After gathering masked positions for the reconstruction heads, the working shape becomes (M, D) where M is the total number of masked tokens in the batch.

Default (ViT‑S/5). Same arch=vit_small as encoder but with depth=4, postnorm=true — configs/polarmae.yml:43-54.

Fine‑tuning: semantic segmentation ¶

Overview & pipeline ¶

For downstream semantic segmentation, the pretrained encoder is reused as a feature extractor, the MAE masking and reconstruction heads are dropped, and three new components are added: a feature‑aggregation step, a PointNet++‑style upsampler that lifts token‑level features back to per‑point features, and a final segmentation head that produces class logits at every point.

Top‑level Lightning module. SemanticSegmentation — polarmae/models/finetune/semantic_segmentation.py:29-336. Wired up by the task entrypoint polarmae/tasks/semantic_segmentation.py and configured via configs/part_segmentation_polarmae_fft.yml (full fine‑tuning) or configs/part_segmentation_polarmae_peft.yml (linear probing).

Constructor pieces (semantic_segmentation.py:65-86):

self.encoder      = encoder         # same TransformerEncoder as pretraining
self.seg_decoder  = seg_decoder     # default: None (no transformer decoder)
self.upsampler    = PointNetFeatureUpsampling(in_channel=D, mlp=[D, D])
self.seg_head     = SegmentationHead(
    encoder_dim     = D if (seg_decoder is None and condition_global_features) else 0,
    label_embedding_dim = 0,
    upsampling_dim  = D,
    seg_head_dim    = 512,
    seg_head_dropout= 0.5,
    num_seg_classes = num_classes,
)

With the default config (seg_decoder: null, condition_global_features: true), the path through the network is:

  1. Tokenize + encode the unmasked event with the pretrained encoder.
  2. Aggregate encoder hidden states from layers [3, 7, 11] (§ Token feature aggregation).
  3. Optionally append a global max‑pool + mean‑pool of the token features (the "condition on global features" branch).
  4. Use PointNetFeatureUpsampling to interpolate token features back to the original points (§ Feature upsampling).
  5. Pass the per‑point features through SegmentationHead for class logits (§ Segmentation head).

Masking is off during fine‑tuning. SemanticSegmentation.forward() (semantic_segmentation.py:184-188) calls self.encoder.prepare_tokens(...) — not prepare_tokens_with_masks(...) — so every patch is visible to the encoder.

Token feature aggregation ¶

Purpose. Build a richer token‑level feature by mixing intermediate transformer layers, rather than using only the final layer.

Where implemented. Helper TransformerEncoder.combine_intermediate_layers() — polarmae/layers/encoder.py:111-121. Invoked at polarmae/models/finetune/semantic_segmentation.py:198-203:

token_features = self.encoder.combine_intermediate_layers(
    output,
    out['emb_mask'],
    self.hparams.seg_head_fetch_layers,    # [3, 7, 11] by default
)   # (B, T, D)

Each fetched layer's hidden state is first run through masked_layer_norm() (masking.py:119-143), then the fetched layers are stacked and averaged.

Global feature conditioning (semantic_segmentation.py:205-213, only active when condition_global_features: true and there is no seg_decoder):

token_features_max  = masked_max(token_features, out['emb_mask'])    # (B, D)
token_features_mean = masked_mean(token_features, out['emb_mask'])   # (B, D)
global_feature = torch.cat([token_features_max, token_features_mean], dim=-1)  # (B, 2D)

The 2D global vector is later broadcast over every original point and concatenated to the upsampled features (semantic_segmentation.py:229-234).

Default (full fine‑tuning). seg_head_fetch_layers: [3, 7, 11] (configs/part_segmentation_polarmae_fft.yml:51); condition_global_features: true (line 50). With seg_decoder: null (line 39), the segmentation runs directly on the aggregated encoder features.

Feature upsampling (PointNet++‑style) ¶

Purpose. Bring the T token‑level features back up to the original N points. Implementation follows PointNet++: inverse‑distance weighted KNN interpolation in 3D, optionally concatenated with per‑point xyz, then a small per‑point MLP.

Where implemented. Class PointNetFeatureUpsampling — polarmae/layers/feature_upsampling.py:11-94. Instantiated at semantic_segmentation.py:74-77 with in_channel=D, mlp=[D, D]. Forward call at semantic_segmentation.py:219-227:

x, idx = self.upsampler(
    points[..., :3],            # xyz1: (B, N, 3) — original points
    out['centers'][:, :, :3],   # xyz2: (B, T, 3) — patch centers
    points[..., :3],            # points1: (B, N, 3)
    token_features,             # points2: (B, T, D)
    lengths,                    # valid points per event
    batch_lengths,              # valid tokens per event
    point_mask,                 # (B, N) bool
)   # x: (B, N, D)

Mechanism (feature_upsampling.py:29-93):

  1. For each original point in xyz1, find K=5 nearest patch‑center neighbours in xyz2 via knn_points (line 49‑51).
  2. Compute inverse‑distance weights, normalize so they sum to 1 (lines 53‑56).
  3. Gather token features at those neighbours and compute their weighted sum (lines 62‑66) → (B, N, D).
  4. Concatenate the original xyz (points1) onto the interpolated features → (B, N, D+3) (lines 72‑75).
  5. Apply the MLP [Conv1d(D+3 → D) → MaskedBN → ReLU] × 2 (lines 86‑90) → (B, N, D).

Segmentation head ¶

Purpose. A small 1×1‑convolutional classifier that turns per‑point features into class logits.

Where implemented. Class SegmentationHead — polarmae/layers/seg_head.py:7-62.

Internal layout (seg_head.py:20-35):

self.conv1 = Conv1d(2D + 0 + D, seg_head_dim, 1, bias=False)   # in = 3D when condition_global_features=true
self.bn1   = MaskedBatchNorm1d(seg_head_dim)
self.dropout1 = Dropout(seg_head_dropout)

self.conv2 = Conv1d(seg_head_dim, seg_head_dim // 2, 1, bias=False)
self.bn2   = MaskedBatchNorm1d(seg_head_dim // 2)

self.conv3 = Conv1d(seg_head_dim // 2, num_seg_classes, 1)     # final classifier

Input channel breakdown (seg_head.py:20-25 + semantic_segmentation.py:79-86, 229-234):

  • upsampling_dim = D = 384 — per‑point features from the upsampler.
  • 2 · encoder_dim = 2D = 768 — only when condition_global_features=true: the broadcasted [max‑pool, mean‑pool] global features.
  • label_embedding_dim = 0 — there is no event‑level class label embedding for PoLAr‑MAE (placeholder for ShapeNet‑style part segmentation).

So in the default config the conv1 input dimension is 3D = 1152.

Loss & data flow ¶

Loss. Choice between NLL or a Softmax Focal loss (semantic_segmentation.py:92-106). The PoLAr‑MAE fft config uses loss_func: focal (configs/part_segmentation_polarmae_fft.yml:54), implemented as SoftmaxFocalLoss in polarmae/loss/focal.py. Per‑class weights come from the DataModule and are copied into the loss at setup (semantic_segmentation.py:154).

Loss application (semantic_segmentation.py:265-268) gathers predictions and labels only at valid points:

loss = self.loss_func(
    out['x'][out['point_mask']],
    labels.squeeze(-1)[out['point_mask']],
)

Validation reports val_acc, val_macc, val_precision, val_mprecision, val_f1_score, val_f1_score_m, plus instance and category mIoU via compute_shape_ious (polarmae/eval/segmentation.py).

Notation note. The diagram labels the patch construction step as "Ball query + Masking", but in the code these are two distinct operations: PointcloudGrouping performs the ball query (and per‑patch reduction); a separate VariablePointcloudMasking module produces the MAE mask over tokens.
